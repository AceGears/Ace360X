# Patches to Xenia Canary

Applied in filename order to `native/xenia-upstream` at CMake configure time by
`native/cmake/ApplyXeniaPatches.cmake` (idempotent). Upstream commits are never edited;
the submodule pointer pins the upstream version. Each patch should be small, explain
itself in this table, and be offered upstream where it makes sense.

| Patch | Why |
|---|---|
| 0001-cmake-android-platform-sources | `xe_platform_sources()` had no Android branch, so no platform files were compiled. Adds POSIX + `_android` files. Adds `XENIA_DISABLE_WERROR` so NDK-clang warnings are logged rather than fatal while the Android port is brought up. |
| 0002-cmake-no-sdl3-on-android | SDL3 isn't used on Android; skip building it and leave the `SDL3` interface target empty. |
| 0003-android-source-fixes | Bit-rot in Android code paths found by the first NDK build: `window_android` uses the new `OnActualSizeUpdate(…, WindowResizeAction, …)` signature; `imgui_drawer` gates fontconfig/GTK/embedded-font code to desktop Linux; `mutex.cc` casts `pthread_t` portably (it's `long` on bionic); `threading_posix` skips robust mutexes (not in bionic — process-death recovery isn't needed inside one app) and fixes const-correctness of the Android pre-API-26 thread name helper; removes a stub `SetAttributes` in `filesystem_android` that duplicated (and was worse than) the POSIX one. |
| 0004-shader-script-error-output | `compile_shader_spirv.py` crashed with a `TypeError` while printing tool errors (bytes vs str), hiding the real message. Tooling-only. |
| 0005-android-content-uri-game-launch | Lets a game be launched from a Storage Access Framework `content://` URI (ISO, single-file STFS/CON/LIVE/PIRS packages) so the app needs no storage permission. Extends upstream's existing `IsAndroidContentUri`/`OpenForAndroidContentUri` support to `OpenFile`, `MappedMemory::Open`, file-type detection, `RunTitle` and package size checks via new `PathExistsAnyScheme`/`FileSizeAnyScheme`/`IsNonHostPath` helpers. Not covered: extracted XEX folders, multi-file SVOD/GoD, ZAR. |
| 0006-android-input-driver-registration | Registers Ace360X's Android controller driver (`native/host/android_input_driver.cc`) as the `android` HID option in `EmulatorApp::CreateInputDrivers`, so `hid=any` picks it up on Android. |
| 0007-android-aaudio-registration | Registers Ace360X's AAudio backend (`native/host/aaudio_audio_system.cc`) as the `aaudio` APU option ahead of `nop`, so `apu=any` gives sound on Android. |
| 0008-external-tree-provider | Adds a generic `ExternalTreeProvider` hook to `xe::filesystem` (scheme-prefixed virtual directory trees). `GetInfo`, `ListFiles`, `FileHandle::OpenExisting`, `OpenFile`, `MappedMemory::Open`, the `*AnyScheme` helpers and `HostPathDevice::Initialize` route matching paths to it. Ace360X registers an `acetree://` provider backed by Android SAF folders, so extracted games (folder + `default.xex`) mount through upstream's unchanged `HostPathDevice`. |
| 0009-svod-external-tree | Games on Demand (SVOD): the `.data` fragment-folder existence check uses `PathExistsAnyScheme`; listing and mapping fragments already go through the hooked helpers. |
| 0010-a64-ppc-fp-semantics | Brings the ARM64 (a64) JIT's floating-point results in line with what upstream's x64 backend and real Xbox 360 hardware produce, found by `xenia-cpu-ppc-tests --cpu=a64` on an ARM64 runner (see `docs/reports/cpu/`). (1) `ARITHMETIC_NEGATE_RESULT` was ignored, so `fnmadd`/`fnmsub`(s) and `vnmsubfp`(128) returned the un-negated value; the result is now negated after rounding, leaving NaN signs alone. (2) An invalid operation (e.g. `inf*0`) produced the x86/ARM-style negative default NaN; PowerPC's is positive (`0x7FF8000000000000` / `0x7FC00000`). (3) Multiply-add NaN priority is frA, frB, frC (HIR src1, src3, src2), not src1, src2, src3. (4) `vmaxfp`/`vminfp` return vA if it is NaN, else vB, quieted; NEON prefers any signalling NaN. To be offered upstream. |
| 0011-a64-bit-exact-estimates | `fres`, `vrefp`(128), `vlogefp`(128) and `vexptefp`(128) on the a64 JIT used exact division / `exp2` / `log2`, which differ from the console's estimates in the low bits (and in special cases such as `log2(0)` = −inf). Upstream's x64 backend notes titles depend on the exact bits (5454082B). The a64 sequences now call the shared, bit-exact `ppc::Estimate*` functions from `ppc_estimates.cc` via `CallNativeSafe`. Slower than a native table lookup; a NEON table version can come later with measurements. |
| 0012-a64-dot-product-rounding | `vmsum3fp128`/`vmsum4fp128` (inline NEON `DOT_PRODUCT_3/4` sequences) on the a64 JIT rounded the float64 sum to nearest; the console's result is closer to round-toward-zero. Uses the same conversion as upstream x64's default `use_fast_dot_product` path (which upstream says matches the console in about 97% of cases; its exact model is x64-only for now). |
| 0013-gpu-activity-log | Diagnostics only. Logs "GPU activity: guest swap #N …" on the first guest frame swap and then at most every 5 s, with swaps and draw calls since the last line. Device logs had no way to tell whether a game ever produced a frame. Not intended upstream as is. |
| 0014-presenter-activity-log | Diagnostics only. Logs "Presenter: paint #N …" on the first paint and then at most every 5 s: how many paints reached the screen, failed, or found the surface outdated, and whether guest output is active. Together with 0013 this separates "the game draws nothing" from "frames are lost before the screen". Not intended upstream as is. |
| 0015-present-letterbox-color | Adds cvar `present_letterbox_color` (0xRRGGBB, default black = upstream behaviour) for the area around the guest output. Debug builds of the app set dark blue so a device tester can see whether the presenter's output reaches the screen at all. Could be offered upstream as a small option. |
| 0016-swap-diagnostics | Diagnostics only, off by default. `ace_swap_stats` logs how much of the guest front buffer in guest memory is non-zero at each swap (with `readback_resolve=full` this shows whether rendering + resolve produced pixels); `ace_swap_debug_clear` paints the left half of the guest output magenta after the gamma pass. Verified on Mesa lavapipe with the user's capture: 74 % non-zero with readback (0 without), and a half-magenta image. |
| 0017-vulkan-disable-features | Diagnostics only, off by default. `ace_vulkan_disable_features` lists optional Vulkan features/extensions to treat as unsupported after device creation, so Xenia takes its fallback paths; used to bisect driver problems on the phone. Every group used by the replay screen renders the reference capture correctly on Mesa lavapipe. |
| 0018-resolve-and-pipeline-diagnostics | Diagnostics only, off by default. `ace_resolve_debug_clear` paints colour render target 0 magenta right before each resolve (tests resolve + readback + front-buffer texture load without the guest's draws); `ace_pipeline_debug_permissive` builds draw pipelines without culling or depth/stencil rejection; with `ace_swap_stats`, each resolve logs its destination. Verified on Mesa lavapipe. |
| 0019-pixel-shader-and-blend-diagnostics | Diagnostics only, off by default. `ace_ps_debug_solid` substitutes a fixed fragment shader (opaque magenta to colour target 0) for every guest pixel shader at pipeline creation, so the picture shows whether guest geometry reaches rasterization; `ace_pipeline_debug_no_blend` builds draw pipelines with blending off and a full colour write mask. Verified on Mesa lavapipe with the frame-900 capture (all four replay variants produce non-zero readback; solid + no blend + permissive gives a fully magenta frame). |
| 0020-pixel-shader-stage-diagnostics | Diagnostics only, off by default, in the SPIR-V translator. `ace_ps_debug_output` overrides what a translated pixel shader writes to colour target 0 after the guest code ran (1 magenta, 2 interpolator 0 as colour, 3 alpha forced to 1); `ace_ps_debug_no_kill` removes guest kills and the alpha-test discard; `ace_ps_debug_white_textures` makes texture fetches return 1.0. Verified on Mesa lavapipe (reference values in `TraceReplayActivity.VARIANTS`). |
| 0021-init-sample-mask-output | **Fix (candidate, awaiting device confirmation).** The SPIR-V translator declares the `gl_SampleMask` output for every non-FSI colour pixel shader, but only the alpha-to-coverage code wrote it, and that code is skipped for shaders with early fragment tests and when colour target 0 is not written. A declared but unwritten output is undefined in Vulkan; Mesa lavapipe keeps full coverage, while on the Qualcomm Adreno 840 (driver 07/01/26) every translated pixel shader produced no pixels although a hand-written shader in the same pipeline did. In the user's captures 11 of 13 translated pixel shaders never wrote the mask. Now full coverage is stored at the start of `main`; cvar `ace_ps_init_sample_mask=false` restores upstream behaviour for comparison. Lavapipe output unchanged; all dumped shaders pass `spirv-val`. To be offered upstream once confirmed. |
| 0022-vulkan-dump-translated-shaders | `dump_shaders` now also writes translated SPIR-V on the Vulkan backend (the D3D12 backend already did); used to find 0021. |

To regenerate a patch (each is relative to the tree with all earlier patches applied): edit files in `native/xenia-upstream`, run
`git -C native/xenia-upstream diff -- <files> > native/patches/NNNN-name.patch`, then
`git -C native/xenia-upstream checkout -- .`.
